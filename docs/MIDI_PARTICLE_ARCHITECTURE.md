# ozo GLINT — 架构设计 0.1.0

日期：2026-10-10

状态：2026-10-10 已按正式名称 ozo GLINT 重建 0.1.0 原型及最简界面；四组核心/Processor/AU/VST3 测试通过，并验证旧版 VST3 状态恢复和 MIDI 输出一致。实际 DAW 兼容性（包括旧工程恢复）和跨音源调音仍待验收。范围见 [实现说明](../plugins/glint/README.md) 与 [验证记录](../plugins/glint/VALIDATION.md)。

产品正式名称为 **ozo GLINT**。本次仅更名子工程及统一重新打包命名，版本保持 0.1.0，不扩大 MIDI 生成或声学功能范围。本文不包含 UI/UX 设计。

## 1. 产品决策

**一句话：保留演奏，在它周围自动长出有节奏、有轻重、会消散的附加音符；用户主要只调一个强度。**

首版是演奏驱动的 **MIDI 生成效果器**，不是音频颗粒 Delay，也不是自带钢琴的乐器。它接收 MIDI，生成新的 Note On/Off，交给下游音源发声。

核心承诺：

- 原始演奏不被量化、移调、降力度或人为延迟。
- 一个主宏即可从少量回应推到明显的伴随织体。
- 三种 Character 改变生成规则，而不是冒充三种内置音色。
- 不要求用户设置音阶、填写步进、计算反馈量或配置调制矩阵。
- 生成规模有上限，不把附加音符递归送回自身，无无限增长。
- 清楚区分“发出音符结束指令”和“外部音源已经静音”。

**不承诺：**任意音源都像 NOIRE；保证不发生和声碰撞；逐音符音频分离；任意宿主免路由；MIDI 力度等于响度；所有异常宿主状态下都能送出最后一条 Note Off。

## 2. 继承 PRISM 的理念，而不是照搬其音频功能

当前 PRISM 的可迁移原则：

1. **一个音乐意图宏，驱动内部多条曲线。** 用户选择程度，引擎处理技术参数。
2. **Character 是算法性格。** 相同主控范围保持相同含义，但内部策略不同。
3. **默认值可用，边界自动管理。** 不把声部溢出、音符配对等问题推给用户。
4. **主干简单，内部职责清晰。** 不为未来所有可能性预先堆功能。

不迁移 PRISM 的 Auto Match、音频 Mix、Drive、HQ 或 Wild 算法。MIDI 无法测量外部音源的实际响度。首版也不加入 Wild 或专家参数页。

特别改进：宏映射直接属于引擎/Processor，不放在 Editor；关闭界面、宿主自动化、离线渲染时必须得到相同的行为。Character 切换不偷偷把主宏重置到 30%。

项目依据：`src/PluginEditor.cpp:259-304` 的当前主宏映射；`src/dsp/Stages.h:12-80` 的 Character 配置；`src/dsp/SignalChain.cpp:429-499` 的音频响度与混合处理。README 已说明部分参数描述属于历史记录，不作为当前规格。

## 3. 对外控制契约

### 3.1 只有两个调音参数

| 参数 ID | 类型 / 默认 | 音乐含义 |
|---|---|---|
| `amount` | 0–1；默认 0.30 | 附加音符的整体活跃程度 |
| `character` | ECHO / BLOOM / PULSE；默认 BLOOM | 生成规则的性格 |

Amount 内部联动候选事件速率、活动持续时间、粒子力度分布、八度分布与适量时间变化，但**不修改原始 MIDI**。

- 0：停止生成。Add 模式仍传原始输入；Particles 模式不输出新的音符。
- 低：少量、轻柔、靠近原音区的回应。
- 中：可辨识的伴随音符，具有有限的音区和时间变化。
- 高：更多、更长、更宽的生成活动；仍有固定声部及事件速率上限。
- Amount 归零取消未发出的粒子，并结束插件自己仍按住的生成音符；共享踏板和外部音源 release 仍可能留声。

Amount 不是 Dry/Wet，也不保证听感响度单调增长。不能为了增加 Amount 而同时无限增大密度、力度与长度。

### 3.2 一个一次性的输出设置

`outputMode` 为项目状态设置，不作为演奏自动化参数。

- **Add（默认）**：原始 MIDI + 生成音符，适合放在音源之前，接线最少。
- **Particles**：只输出生成音符，适合独立的粒子音源轨。

默认 Add 的原因是插入后不丢失主体演奏。需要粒子独立音色、空间及更可控生命周期时，使用 Particles。两者不是音质等级，保证范围不同。

输出模式仅在 MIDI 空闲时应用：没有原始按键、保持踏板或未完成的生成持音。活动中提出的更改延后应用，避免在两个模式之间交叉清理音符。它不是可以随意扫动的“Mix”。

### 3.3 不暴露的技术控制

不单独暴露 Density、Scatter、Decay、Register、Gate、Pre-delay、Feedback、Seed、Sync/Free 或和弦类型。它们由主宏、Character 和宿主时钟决定。验证后如发现确有不可替代的需求，再增加参数，而不是预先加入专家页。

三种 Character 都使用宿主速度作为时间尺度：PULSE 落在网格上，BLOOM 在该时间尺度上自由变化，ECHO 保留清楚的重复间隔。速度不可用时使用 120 BPM；无效速度不能造成除零或无穷时间。

### 3.4 Character 定义

| 性格 | 时间规则 | 音符选择 | 听感目标 |
|---|---|---|---|
| ECHO | 以稳定间隔产生回应，少量偏移 | 偏向最近演奏及其顺序，以原音区和上一八度为主 | 仍能听出演奏的影子 |
| BLOOM | 有界的非等距间隔 | 加权选择可用音符，避免连续重复，高强度逐渐扩展八度 | 散开、轻盈、会消散的音符云 |
| PULSE | 固定音乐网格上的概率触发 | 从可用音符池生成稀疏脉冲，不要求编辑步进 | 更清晰的律动伴随 |

ECHO 仍受全局密度和同音安全约束，不保证每一个输入音符都得到固定次数的逐一回声。BLOOM 也不代表内置混响。

### 3.5 初始调音锚点，不是已验证的最终数值

以下作为 BLOOM 的原型起点；其他 Character 在相同 Amount 下改变分布与节奏，而不是另起一套控制含义。

| Amount | 活动充分时的候选事件速率 / 四分音符拍 | 单次活动最长跨度 | 粒子力度相对所选源音符 | 音区 |
|---|---|---|---|---|
| 10% | 约 0.5 | 约 1 拍 | 约 0.30 | 原位为主 |
| 30% | 约 1 | 约 2 拍 | 约 0.45 | 原位 / +1 八度 |
| 60% | 约 2 | 约 4 拍 | 约 0.50 | 原位 / +1，少量 +2 八度 |
| 100% | 约 4 | 约 8 拍 | 约 0.55 | 原位 / +1 / +2 八度 |

实际输出会因活动衰减、可用音符、碰撞和预算而减少。短促持续更新的演奏可以持续补充活动，但输入停止后生成活动必须有限结束。30% 默认值要通过听测确认“一开始就能听见区别，又不盖过主体”，不能只以数字验收。

## 4. 音乐引擎：从输入事件到粒子

### 4.1 SourceTracker：记录演奏事实

按 `(MIDI channel, pitch)` 记录：按键计数、最近力度、最近触发时间，以及 CC64 延音、CC66 选择性延音状态。

- 相同音高的多次原始 Note On 需要计数，不能用一个 bool 代替。
- Note On velocity=0 按 Note Off 处理。
- 优先选择物理按住的音，其次是踏板保持的音；较新的演奏获得更高权重。
- 不做和弦命名、调式推断或复音音频分析。
- 全部释放后，可保留一个有限的尾部音符快照，只供剩余活动使用；新的 Note On 替换旧尾部快照。
- 踏板下的新和弦优先，但不宣称能推断所有转调意图。八度扩展也不能消除旧尾音与新和弦的碰撞。

不等待一个额外的“和弦收集窗口”，不延迟原始输入；生成器在首颗粒子的前置间隔内自然获得已到达的音符。

### 4.2 ActivityEnvelope：整片云的活动，不是每个按键一串反馈

每次原始 Note On 更新一个全局、有上界的活动状态。

- 和弦中几个同时到达的 Note On 不把事件密度乘以音符数。
- 力度影响活动初值及生成力度，不直接成为不受限的声部数量。
- 可以使用 `activity = max(activity, strike(velocity))` 一类有界更新，不使用无限累加反馈。
- 活动从最近的有效击键开始衰减；持键/踏板提供音符候选，不自动变成无限循环。
- 释放键盘不重新把活动拉满；只让剩余活动完成。
- 首版无 Infinite、Latch 或 Freeze。

初版硬上界建议：最后一次输入之后，生成窗口不超过 8 拍且不超过 8 秒；这些是防无限增长的工程界限，不是 UI 参数。

### 4.3 ParticlePlanner：一个全局调度器

所有音符共享候选事件速率，不为每个输入音符创建一条独立无限 Delay 链。

每次候选事件：

1. 检查活动强度及事件预算。
2. 按 Character 决定时间和触发概率。
3. 从源音符池选择音符，保留其通道归属。
4. 在许可八度中选取音高。
5. 根据源力度、Amount 和活动衰减生成力度。
6. 分配音符长度，再交给安全层申请发声。

音高首版只来自演奏音符及整数八度，不加入随机五度、半音或自动调式纠正。超出 MIDI 0–127 的候选被跳过或在许可八度内重选，不硬裁到边缘音高。

时间随机使用正值间隔或有界网格偏移，不能产生负时间、过去事件或无限重抽。避免连续重复与碰撞的重选次数也有固定上限；选不到就跳过。

新击键可以补充活动，但不能不断推迟已经安排的首颗粒子，导致快奏时永远没有输出。插件生成的事件不重新进入 SourceTracker。外部误接 MIDI 回环不在这一内部防递归保证内。

### 4.4 VoiceLedger：每条生成 Note On 必须有归属和结束条件

记录生成音符的 token、通道、音高、开始时间、固定结束拍位、硬结束时间及踏板保持状态。

- Note Off 在 Note On 被接受时就取得保留容量，不依赖之后队列还有没有空间。
- Amount / Character 变化只改变后续生成，不重新抽取已经开始的音符，也不把它们的结束无限后推。
- 固定结束拍位可随宿主速度转换为样本时间；另有硬时间上限防止极端减速拖出长持音。
- 建议 MIDI gate 起点为 0.125–0.5 拍、硬上限 2 秒；这不等于音源的音频尾音长度。
- 初版最多 24 个生成占用，包含已经发出 Off、但仍可能由支持的保持踏板维持的占用。
- 候选生成速率硬上限建议 24 次 Note On/秒；按连续时间限流，不按 block 数量设音乐节奏。
- 满载时丢弃新的粒子，不能挤掉必要的 Note Off，也不削减原始演奏。

上述数字是原型安全起点。音源的内部 release 声部、内部 sustain、采样器分层等无法由 MIDI 账本精确计数。

## 5. 两种输出方式的真实边界

### 5.1 Add：优先简单接入

```text
MIDI 输入 → ozo GLINT → 原始事件 + 生成事件 → 外部音源
```

“保留原始演奏”指插件不主动改写原始事件的音高、力度和到达时间；下游音源仍可能因额外复音发生声部抢占，不承诺声音完全不变。

同一 MIDI 1.0 通道/音高无法可靠标记“这是原声，那是粒子”。因此使用保守仲裁：

- 原始按键或已知踏板保持音占用的键位，不新生成同键粒子；在许可八度中有限重选，仍无候选则跳过。
- 生成音符之间也不重叠相同通道/音高。
- 原始 Note On 到达时若同键粒子仍被插件按住，先发该粒子的 Note Off，再原时标传入原始 Note On；原声优先。
- 如果旧粒子已经发出 Off 但由踏板保持，不重复发送 Off；记录其残留，不假设它已经消失。
- token 防止陈旧的计划 Note Off 在原声重击后误关新音，但不能改变外部音源的 MIDI 1.0 配对语义。

CC64/66 透传意味着原声和粒子共享踏板。Amount=0 或停止生成，只能释放插件仍按住的键，不能保证立即切断踏板中的粒子。

**不得为了清理粒子擅自发送全通道 CC123、CC120 或强行释放 CC64/66，破坏原声。** 踏板长期保持且生成预算满载时，生成器安全变稀或停发，直到占用可回收。

这是保守、非隔离模式。对于外部音源未知的同键重触发、额外保持控制或声音 release，不给出逐声部严格控制保证。

### 5.2 Particles：需要独立音色和生命周期时使用

```text
原始 MIDI ──┬─────────────────────────→ 主体音源
            └→ ozo GLINT（Particles）→ 粒子音源 → 可选音频效果
```

- 只发送生成的 Note On/Off。
- CC64/66 用于维护输入音符池，不传给粒子音源。因此生成器能更明确地管理自己发出的按键长度。
- 首版其他普通 CC、程序切换、压力及 Pitch Bend 不向此输出转发，避免隐式改变独立粒子音源。该模式不是完整的 MIDI Thru。
- 输入的紧急通道消息触发对应生成声部清理，不能成为无限继续生成的起点。
- 粒子材质、包络、混响、漫射和音量由独立音源/效果负责。

Particles 仍无法控制音源自己的 release 尾音，不等于音频静音开关。它也需要宿主提供输入分发与 MIDI 输出路由。

### 5.3 对控制消息的约定

控制消息按通道处理，不得只处理 Note On/Off：

- **CC64 Sustain**：踏板按下保持相关释放音；抬起时回收不再受其他保持条件约束的占用。
- **CC66 Sostenuto**：记录踏板按下瞬间的保持集合，不能简单当第二个 CC64。
- **CC120 All Sound Off**：取消该通道生成活动并清理生成归属；Add 透传宿主明确发出的清声命令。按键/控制器状态按消息语义处理，不能顺手重置所有控制器。
- **CC123 All Notes Off**：按释放按键语义更新状态；共享踏板仍可能维持声音，不等同于 CC120。
- **CC121 Reset All Controllers**：更新保持控制器状态并回收相应残留，不将仍按住的原始音符无条件全部清空。

更广泛的保持机制、MPE、MIDI 2.0 不在首版支持范围。Add 可保留适配层交付的其他事件，但不声称引擎理解其全部音源语义。

## 6. 软件模块和依赖方向

```text
                  参数 / 项目状态
                         │
                         ▼
                  MacroMapper
                  amount + character
                         │ PolicySnapshot
                         ▼
宿主 MIDI → HostAdapter → ParticleEngine ───────────→ HostAdapter → MIDI 输出
                │          │
                │          ├─ SourceTracker
                │          ├─ ActivityEnvelope
                │          ├─ ParticlePlanner / NoteSelector
                │          └─ VoiceLedger / OutputArbiter
                │
                └────────→ MusicalClock
                           sample clock + tempo + transport epoch
```

### 6.1 核心层

`ParticleEngine` 为宿主无关的 C++17 库，输入事件视图、块时钟和控制快照，输出有界的新增事件及必要的仲裁动作。

- 不依赖 Editor、文件系统、系统时钟或音源。
- 不必为每个框图强行建立抽象基类；先用明确的小型值类型/模块组合。
- 可以直接在离线测试中喂入 MIDI，获得事件轨迹。
- `PolicySnapshot` 是从宏导出的只读策略，不是第二份可独立保存的参数真相。

关键数据：`SourceKeyState`、`ActivityState`、`NextCandidate`、`GeneratedVoice`、`TransportEpoch`。正常生成只需要下一个候选事件和有限活动声部，不预先堆出几千条远期事件。

### 6.2 适配层

HostAdapter 负责 JUCE 事件转换、宿主时间、状态持久化及格式差异。音频不进入生成算法；若某个宿主需要音频总线才能运行 MIDI 输出实例，只在兼容外壳中处理透明音频通过或空总线约定。

独立产品目标，不复用 PRISM 的音频 SignalChain 或其 Processor 参数布局。可复用项目的构建/测试方式，不为这个产品先重构 PRISM。

### 6.3 状态和自动化

保存：state schema version、Amount、Character、Output Mode、内部固定随机 seed。

不保存：正在按住的按键、活动云、待发音符、音源声部及暂态踏板残留。工程重开从干净 MIDI 状态开始；输入流负责恢复演奏状态。

运行中应用预设/状态必须先结束旧的生成按键、取消旧候选；不能直接覆盖账本。共享踏板残留不能因换预设被错误认定为已静音。

seed 不提供首版调音控。随机抽样基于确定的事件序号，而非 callback 次数或墙钟；相同初始状态、完整 MIDI/控制/transport 输入得到可重复输出。播放循环使用固定的循环重置规则，以免每次回放无意变成另一版；从片段中间开始没有历史输入时，不保证与从头播放同一结果。

## 7. 实时时序与失败处理

### 7.1 时钟

- 原始事件沿用适配层提供的 sample offset，不做额外量化或前瞻等待；插件声明不人为增加原始路径延迟。
- 在宿主播放且 PPQ 有效时，用宿主音乐时钟定位网格。
- 停播实时弹奏时，不能依赖冻结的 PPQ；使用连续样本时钟按当前/最近有效速度推进。
- 速度变化仅改变目标拍位的时间换算，不把过去的候选补发成爆发，也不无限延长 Note Off。
- 块区间统一为 `[blockStart, blockEnd)`；边界事件只在一个块内发出。
- 同时间戳保留适配层已交付的原始事件顺序；同键粒子释放就地插在原始重击前。不能把所有输入随意重排为“全部 Off 再全部 On”。
- VST3 音符事件与控制器映射可能从不同机制到达，不能保证恢复宿主未提供的跨类型原始顺序。

### 7.2 Stop / Seek / Loop / Bypass

检测状态边沿，不在每个停播 callback 中不断清空引擎。

1. 取消旧 epoch 尚未发出的候选 Note On。
2. 对插件仍按住的生成音符安排必要 Note Off。
3. 清除旧生成活动，建立新的时钟 epoch。
4. 原始持音账本及共享踏板残留按实际 MIDI 语义保留；不能仅因 epoch 改变就回收它们。
5. 清理后同块新到达的有效实时 Note On 可以启动新活动。

插件内部 Bypass：Add 回到原始 MIDI 通过；Particles 停止新生成并结束自有按键。不要混同于宿主完全暂停处理的硬 Bypass。

如果宿主停止调用插件或根本不转发最后输出，插件无法保证送出清理事件；宿主停止/旁路的行为必须实测。安全命令不能被包装成无条件“永不挂音”的宣传保证。

### 7.3 资源

- 核心路径固定容量、无锁、无文件 I/O、无后台线程依赖，不在回调中临时申请堆内存。
- 固容量覆盖源键状态、生成声部、候选和必要 Off；回收不依赖 UI 线程。
- 内部过载时优先保护 Off 和原始演奏，拒绝新粒子；不积压到后续块集中补发。
- 宿主输入规模与 SysEx 可能不受插件控制。适配层采用预分配与输入缓冲复用，并用分配检查器验证正常支持范围；不承诺任意大小输入既无损复制又绝无分配。
- 音频线程只写有界诊断计数/快照，未来界面只读，不能阻塞处理。

### 建议的首轮验证目标，不是支持声明

| 平台 / 格式 | 目标宿主 | 验证重点 |
|---|---|---|
| macOS / AU MIDI Processor | Logic Pro | 原生 MIDI FX 位置、键盘/片段输入、踏板、停止与旁路行为 |
| macOS / VST3 | REAPER | MIDI 输入输出、前置串联、分轨、事件回录与时标 |

Logic Pro 和 REAPER 是架构验证的建议基线，不代表已确认用户的主要宿主。Ableton、Cubase、FL Studio 等不因格式相同就自动获得支持结论。

## 9. 验收：先证明行为正确，再证明音乐性

### 9.1 核心自动化测试

- Add + Amount=0：适配层获得的原始事件保持时标及内容，无生成 Note On。
- Particles + Amount=0：无新音符，并能结束此前插件自己按住的生成音。
- 单音、和弦、密集演奏：事件速率和声部数受同一全局预算约束。
- 生成音高仅来自合法源音符及允许八度；力度始终是合法的非零 Note On。
- 每条已发送的生成 On 都有结束路径；不会因满载丢掉必要 Off。
- 重复原始 On、velocity=0、同音重击、原声与粒子碰撞不产生陈旧 Off。
- CC64/66 交互、CC120/121/123、长踏板满载和恢复均有明确事件轨迹。
- Amount/Character 改变只影响规定范围，模式更改不能破坏持音。
- Stop、Seek、Loop、内部 Bypass、运行中状态加载没有旧候选穿越 epoch。
- 停播仍可实时演奏；PPQ 冻结时生成和 Off 仍会推进。
- 正常负载下，在 32/64/128/512/1024 样本块划分及零长度块边界下，事件轨迹保持一致或仅有定义过的样本取整差异。
- 相同初始状态和完整输入重复渲染可复现；异常速度、采样率切换、空输入和长静默无失控生成。

### 9.2 宿主回录验收

先测试最小输入→输出，再测试真实生成。回录并检查 Note On/Off、力度、通道、踏板与时间戳；检查插件无界面时、离线导出、停止、旁路和循环的行为。

外部音源试听不能替代事件层测试；自建测试宿主通过也不能替代实际 DAW 路由验收。

### 9.3 音乐性验收

使用至少三类外部音源：有力度分层的钢琴、短促拨弦/槌击、带明显 release 的合成器。

需要验证：

- 30% 默认值能听见伴随变化，而不是稀到像没工作。
- 推高 Amount 主要增强生成存在感，不只变吵。
- 和弦不会因为多几个输入音就出现数倍密度。
- ECHO、BLOOM、PULSE 不看界面也能辨认其行为差异。
- 原声强拍有前置留白；尾部自然停止，没有机械的无限堆积。
- Add 长踏板触发预算限制时可预测、不爆发；Particles 分轨时音符生命周期更清楚。

纯 MIDI 无法完成外部音频的自动响度匹配。听测应手动控制外部音源和轨道电平，避免把更响误认为更好。

## 10. 首版范围与实施顺序

### 首版纳入

一个 Amount、三种 Character；Add/Particles 输出；有界音符池与活动包络；宿主速度/停播时钟；完整生成音符生命周期；确定性随机与项目状态；AU/VST3 的选定宿主验证。

### 首版明确不做

音频输入分析、颗粒音频缓冲、复音分离、内置采样器、混响/漫射、逐粒子声像、音量匹配、MPE/MIDI 2.0、和弦命名、音阶选择、可编辑步进、调制矩阵、Wild、无限保持、MIDI 文件拖出、第三方插件托管及独立应用。

### 后续实现顺序

1. **宿主通路原型**：证明 MIDI 输入、输出、CC、回录和停止清理可用。通路不成立时先修封装，不能用生成算法掩盖问题。
2. **安全最小引擎**：Amount、BLOOM、两种输出、时钟、SourceTracker、VoiceLedger 和确定性测试。
3. **音乐行为扩展**：加入 ECHO/PULSE，跨音源调试宏曲线，验证默认值与高强度边界。
4. **产品化**：锁定支持矩阵、序列化兼容性、打包和自动化测试；之后再做 UI/UX。

**架构结论：先把它做成一个只需表达“多少”和“什么性格”的 MIDI 伴随生成器。外部音源决定材质，独立音频效果决定空间；不把这些尚未拥有的能力伪装成 MIDI 旋钮。**
