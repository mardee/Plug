### 已验证的致命缺陷（Python 复现 DSP + 真实素材实测）
1. **响度漂移 6.6 dB**：ΔRMS 从 -36dBFS 输入的 +5.08dB 漂到 0dBFS 输入的 -1.49dB。
   根因：OutputStage 固定 +6dB makeup（注释 "was 0"，是补丁）经 intensity=0.8 混合 ≈ +4.8dB，
   大信号时压缩才介入。固定增益补随电平变化的量，无解。
2. **零偶次谐波**：tanh 是奇函数，数学上不可能产生偶次。实测 2次 -190dB / 3次 -21.6dB / 5次 -40.7dB。
   而 PreampStage.h 注释却写 "Adds even-order harmonics"。结果是"硬/刺"而非"温暖"。
3. **压缩器在真实素材上 GR 恒为 0**：dB 域一阶平滑把峰值平均掉了——
   瞬时 dB 中位 -25.2dB，包络 env 最大仅 -18.1dB，而阈值 -10dB，永不触发。
   信号真实峰值 -6.03dBFS 明明超阈 4dB。正确做法：线性域整流/峰值检测再转 dB。
4. **无过采样 → 混叠**：15kHz 输入的 3次谐波 45kHz 折叠到 3kHz（-38.6dB）；
   12kHz 输入的 3/5/7 次全折叠回 12kHz 压在基波上。
5. **intensity 做成干湿混合是设计错误**：每级 `in*(1-w) + proc*w`，
   EQ 变成并联（曲线形状不对），磁带 HF rolloff 被稀释，整体听感"糊一层"而非"经过设备"。
6. 工程缺失：无 AudioProcessorValueTreeState（参数不可自动化）；
   getStateInformation 只存 preset index，intensity 重开丢失；
   无 ScopedNoDenormals；getTailLengthSeconds 返回 0；acceptsMidi 与 CMake 声明矛盾。

### 踩到的 JUCE 9 坑（重要，下次直接避开）
1. **`juce::String(const char*)` 按 Latin-1 解释** → 中文经 juce::String 往返必乱码。
   控制台输出一律走 std::string / const char*，不要过 juce::String。
2. **`Font(float)` 已 deprecated** → 用 `juce::Font(juce::FontOptions(h, juce::Font::bold))`。
3. **参数属性类型是 `AudioParameterFloatAttributes` / `AudioParameterBoolAttributes`**，
   不是 `AudioProcessorValueTreeStateParameterAttributes`（后者只用于 APVTS 内部）。
4. **`juce_VST3PluginFormatHeadless.h` 缺少 include guard** → 只能 include 模块总头
   `juce_audio_processors_headless.h`，不能单独再引它，否则 redefinition。
5. **AudioBuffer 视图构造**：`AudioBuffer(Type* const* data, int numCh, int numSamples)` ✓
   用于把超长 buffer 切成 maxBlock 的子块（SignalChain::process 里已加分块兜底）。
6. **VST3 宿主诊断**：必须 `format->findAllTypesForFile()` 扫出 PluginDescription，
   手搓 desc + uniqueId=0 会报 "No compatible plug-in format exists"。
   JUCE 的 VST3 wrapper 不支持超过 prepareToPlay 声明块长的 buffer（会崩）——
   真实宿主不会这么调，但诊断工具要按块长来。
7. **JUCE 9 的 Oversampling**：`filterHalfBandFIREquiripple` 比 polyphase IIR 阻带更陡；
   4x 与 8x 对混叠抑制差别极小（-61.2 vs -61.8 dB），说明已到测量底噪，用 4x 即可。
   4x FIR 延迟 59 采样，记得 `setLatencySamples()` 上报。

### BUG #1：打开界面必崩（Studio One 加载即 SIGSEGV）

### 1. 染色加猛（Stages.h / SignalChain.cpp）
- Preamp 预增益 `1 + drive*5` → **`1 + drive²*20`**（满档 21x）。
  平方曲线保证小档仍温和、大档直接进 tanh 硬拐点。
- Tape 级饱和 `1 + drive*3` → `1 + drive²*9`，且 SignalChain 不再只喂 60% drive（改为 100%）。
- **Output 级从"极轻抛光"改成第二道饱和**：`0.30 + glue*0.85`，`1 + glue²*6`。
  两级叠加是"猛"的关键——单级再推也只在波形上捏一下，两级才把谐波密度顶上去。
- 压缩阈值 -14-12·glue → -16-14·glue；ratio 系数 0.6+0.6·glue → 0.6+0.9·glue。
- Tone：低架 5.5→7.5 dB，presence 1.2+1.3w → 2.0+3.0w，高架 6.5→8.5 dB。
- **LoudnessTracker 补偿上限 ±18 → ±30 dB**：满档染色会把电平压掉 20 dB 以上，
  不放宽会导致 Auto Match 追不平、bypass 切换音量跳。
- 实测：3 次谐波 -21.6 → -12.0 dB(Tube)；0 dBFS 输入峰值 0.22 → 0.10（多压约 6.8 dB）；
  GR 默认 -3.4 dB，glue 拉满 -11.9 dB；响度漂移仍 0.35 dB；11/11 全绿。

**预设名必须 ASCII**：`juce::String(const char*)` 按 Latin-1 解释字节，中文会乱码。

### 3. 镭射粉彩 UI
- 新文件 `src/ui/ParticleField.h`：4 团缓慢漂移的粉彩光晕 + 一条横移的镭射扫光 + 44 颗上浮粒子

## 第三轮改造：实时频谱背景 + 旋钮主题色

用户要求：① 四个主旋钮各取一个主题色 ② 背景加实时频谱动画（粉彩炫光）
③ 旋钮大小决定频谱与粒子的配色占比。

### 新增文件
- `src/dsp/Spectrum.h` — SpectrumAnalyser：2048 点 FFT + Hann 窗 + 80 个对数分箱
  （22 Hz~20 kHz），`std::atomic<float>` 传给界面，无锁。
  幅度快起慢落（0.55/0.12）；对数箱内取 max 不取平均（平均会把窄带峰值抹平）。
  分析 processBlock **之后**的信号。新增 `getTick()` 供界面判断"有无新数据"。
- `src/ui/TintPalette.h` — 256 级颜色 LUT，**高斯软分配**而非硬切分：
  centre=(cum[i]+cum[i+1])/2，sigma=half*0.95+0.055，四色按 exp(-d²/2σ²) 加权混合。
  硬切分会在边界留接缝。kFloor=0.20 保底。
- `src/ui/SpectrumLayer.h` — 最底层：底色 + 光晕(Image 缓存) + 扫光 + 频谱柱
- `src/ui/PanelLayer.h` — 面板从 Editor::paint 搬出来成为独立组件
- `src/ui/ParticleLayer.h` — 最上层装饰，52 颗
- `src/ui/Layout.h` — 尺寸常量，Editor 与 PanelLayer 共用
- 删除 `src/ui/ParticleField.h`、`src/ui/Backdrop.h`

### 关键架构约束（踩过才知道）
**JUCE 子组件永远画在父组件之上。** 面板原本画在 Editor::paint 里，
意味着任何背景子组件都会盖住面板和文字。所以必须把面板拆成独立组件，
夹在频谱层和粒子层中间 —— 顺序即层级：
```
SpectrumLayer → PanelLayer → ParticleLayer → 旋钮/按钮/表
```
面板做成**上实下透**的垂直渐变（0xEEFFFFFF → 0xB4FFFFFF），频谱才能透上来。
预设按钮背景改半透明（0xE8F4EEFC），否则底部频谱被挡死。

### 配置
- 旋钮主题色经 `slider.getProperties().set(OzoCol::propTheme, i)` 传给 LookAndFeel，
  绘制层自己查 —— 比在 Editor 里硬塞颜色干净。
- 主题色值弧用 `OzoCol::tintGlow()`（同色深浅渐变），**不能**用四色全息，
  否则四个旋钮长得一模一样，看不出谁是谁。
- 粉彩太亮，浅底做文字看不清，每色配了加深版 `OzoCol::tintText[4]`。
- 粒子每颗存固定的 `u`（颜色轴位置），颜色 = `palette.at(u)`。
  u 均匀分布 → 权重一变颜色分布立刻变，不用等粒子重生。

### Air 增强第二轮（23:27 后，针对吉他干声听不出）
- 根因：7k 高架作用在吉他干声上几乎没料可加（吉他能量多在 5k 下），单纯加 gain 无效。
- 改 `Stages.h::ToneStage`：给 Air 新增一条 **4k 钟形 presence 峰**（airPresence biquad，
  Q=1.0，gain = airNorm*5.0*airScale），串在 presence 之后、高架之前。这是直接 EQ、不依赖磁带分量，
  所有角色都显耳。Air 现三动作：高架 + 磁带留存 + 4k presence。
- 响度中性对照：峰 7.0→0.47dB、6.0→0.47、5.0→0.45（K 计权对 4k 敏感，每 1dB 峰≈0.02dB 偏差）。
  定 5.0（默认 Air 约 +2.1dB@4k，拉满 +6.25dB@4k），留 0.05dB 余量。15/15 通过、安装签名、启动存活。

### Air 改为谐波激励（23:33 后，用户点名要"air 不是 presence"）
- 删掉 `airPresence`（4k 峰）—— 它让 Air 听起来像 presence。
- 新增 `AirHarmonicStage`（Stages.h）：经典 exciter 原理，复用现有 `asymTanh` + `Biquad`。
  流程：高架预提亮 air 频段(preDb=airNorm*16*airScale) → asymTanh(drive=1+airNorm*2.5) 产生整数谐波
  → 取纯谐波(shaped-boosted)*0.12 → 高通只留 air 频段(hpHz=airShelfHz*0.62) → DCBlocker → 混合回(x+harm*depth)。
  Air 旋钮现在 = "谐波量"，而非 EQ 峰。保留 air 高架(13dB)做顶层光泽 + 磁带留存。
- 验证 15/15，响度最大偏差 0.36 dB（比 4k 峰版 0.45 更低，因谐波落 10k+ K 计权衰减段，
  恰好证明 Air 现在只作用于高频）。VST3/AU 重签安装、启动存活。

### 用 1-2k 重测响度，发现并修复 autoMatch 根因（23:40 后）
- 用户指出响度测试该用 1000~2000Hz（之前 440Hz 是假阴性）。改 `testLoudnessNeutrality` 为 1000/1250/1500/2000 扫频，分频段报最坏偏差。
- 实测偏差 0.62dB（超 0.5 容忍）。做 air=0 对照仍 0.59dB → **证明 Air 谐波激励器不是元凶**。
- 根因：`LoudnessTracker` 用纯 RMS（inRms-outRms）做 autoMatch，对高频谐波过敏，单频 1-2k 下过度补偿 → bypass 跳 0.6dB。
- 修复：`SignalChain` 加 K 权重滤波器（HP@40Hz + LP@2.5kHz，近似 ITU-R BS.1770），autoMatch 改用 K 加权 RMS。
  偏差降到 **0.40dB**，15/15 通过。这是架构级修正（更科学的响度匹配）。
- Air 的 kHarmNorm 恢复 0.12（之前误降，诊断证明谐波量对偏差仅贡献 ~0.03dB，无关）。
- VST3/AU 重签安装、启动存活。

### Weight 改为低频谐波激励（00:10 后，对应 9/17 凌晨）
- 用户反馈 Weight 在吉他上也不明显（跟 Air 同病：在加没有的东西）。诊断：Weight 在两处共约 16dB 低架
  （WeightStage 预放低架 weightNorm*9*weightScale + ToneStage 低架 weightNorm*7.5），吉他没有低频可加所以听不出；
  贝斯有低频所以用户猜它行。
- 仿 Air 做法新增 `WeightHarmonicStage`（Stages.h，复用 asymTanh + Biquad LP + DCBlocker）：
  预提低(preDb=weightNorm*22*weightScale，比 Air 狠因吉他低频弱) → asymTanh(0.3) 产低频整数谐波
  → 取纯谐波(kHarmNorm=0.10) → 低通只留 2f~6f 身体区(lowShelfHz*6 限 450~950Hz) → 混合回(depth=weightNorm*0.9*weightScale)。
- 顺手解开隐藏耦合：`presenceDb = 2.0 + weightNorm*3.0` 让 Weight 偷偷抬 2600Hz 中频 → 改为固定 +2dB。
- 验证 15/15，1-2k 响度最大偏差 0.28dB（比上一版 0.40 更稳，因解开 Weight→中频耦合）；VST3/AU 重签安装、启动存活。
- 关键模式：旋钮"不明显"多半是"在加该信号没有的频段"，正解是加该频段的谐波（exciter），不是堆 EQ。
