# ozo EZamp

录音棚染色插件。品牌 **ozo**。

一句话：**挂上就能听出声音变贵了，而且 bypass 时音量不动。**

## 信号链

```
Input ──▶ Preamp ──▶ Tape ──▶ Tone ──▶ Comp ──▶ Output ──▶ Mix
          话放      磁带     Pultec   总线压缩   输出变压器
          染色      染色     染色     glue        glue
                  ↑ 整条链路跑在 4x 过采样下 ↑
```

## 参数

| 参数 | 范围 | 作用 |
|---|---|---|
| Input | ±24 dB | 进入染色前的电平 |
| Drive | 0–100% | 染色强度（饱和度） |
| Character | Tape / Tube / Console | 换的是饱和对称性、滤波曲线和压缩性格，不是换预设 |
| Weight | 0–100% | 低频厚度（低架提升 + 同时收紧 40 Hz 以下） |
| Air | 0–100% | 高频空气感 |
| Glue | 0–100% | 总线压缩量（同时压低阈值、加大压缩比） |
| Output | ±24 dB | 输出电平 |
| Mix | 0–100% | 平行混合，只在最终输出做一次 |
| Auto Match | 开/关 | 实时把输出响度追平输入 |
| HQ | 开/关 | 4x / 2x 过采样，两档都抗混叠 |

预设按**染色强度**排，不分乐器也不分总线（乐器/总线是用法，不是音色）：

| 预设 | Drive | 听感 |
|---|---|---|
| Subtle | 16% | 只磨掉数字味的毛边 |
| Warm | 34% | 偶次谐波出来，声音变厚 |
| **Color** | 55% | 默认档，挂上就知道过了设备 |
| Grit | 72% | 谐波开始咬人 |
| Crush | 88% | 峰值被压平，密度上来 |
| Destroy | 100% | 没有安全网，听它烂掉 |

## 构建

需要 JUCE（仓库内 `./JUCE/`，当前为 JUCE 9）。

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
```

产物在 `build/ozoEZamp_artefacts/Release/`，含 VST3 / AU / Standalone。

安装：

```bash
cp -R "build/ozoEZamp_artefacts/Release/VST3/ozo EZamp.vst3" ~/Library/Audio/Plug-Ins/VST3/
cp -R "build/ozoEZamp_artefacts/Release/AU/ozo EZamp.component" ~/Library/Audio/Plug-Ins/Components/
```

### 为什么有这些测试

上一版（StudioChain）的测试断言是「信号有没有变化」，
结果测试全绿、声音难听。这里的四项测的是「变化的方向对不对」：

| 项 | 判据 | 上一版 | 现在 |
|---|---|---|---|
| 偶次谐波 | 2 次谐波真实存在 | −190 dB（等于零） | −13.2 dB（Tube） |
| 响度中性 | bypass 跳变 < 0.5 dB | 6.6 dB 漂移 | 0.35 dB |
| 压缩器 | 增益衰减确实在动 | 0.00 dB（没接） | −3.4 dB（默认）／−11.9 dB（拉满） |
| 混叠 | 3 kHz 不高于测量底噪 | −38.6 dB | 与底噪持平 |

## 界面

### 三层背景，顺序即层级

JUCE 的子组件永远画在父组件之上，而组件之间的顺序由 `addAndMakeVisible`
的先后决定。要让频谱垫在面板**底下**、粒子飘在面板**上面**，面板本身
就必须是一个独立组件，被夹在中间：

```
SpectrumLayer   ← 底色 + 粉彩光晕 + 镭射扫光 + 频谱柱
PanelLayer      ← 面板（上实下透的垂直渐变，让频谱透上来）
ParticleLayer   ← 52 颗粒子
旋钮 / 按钮 / 表
```

两层动画都是 30 fps、不吃鼠标事件、窗口不可见时停画 ——
装饰不该抢音频线程的余量。

### 频谱

`src/dsp/Spectrum.h`：2048 点 FFT + Hann 窗，80 个**对数**分箱（22 Hz ~ 20 kHz）。
线性分箱会把 80 根柱子里的 70 根堆在高频，低频全挤在一起，没法看。

- 幅度做"快起慢落"（起 0.55 / 落 0.12），纯瞬时值会抖得看不清。
- 一个对数箱里压着好几个 FFT bin 时取**最大值**而不是平均 ——
  平均会把窄带峰值抹平，柱状图就趴下去了。
- 分析的是染色**之后**的信号，所以推 Drive 时频谱的变化能直接对上听觉变化。
- 音频线程写、界面线程读，中间只有 `std::atomic<float>`，没有锁。
  FFT 与所有缓冲都在 `prepare()` 里一次备好，`push()` 里零分配。

### 配色权重：旋钮开多大，颜色就占多少

四个染色旋钮各领一色：**Drive 亮粉 / Weight 薰衣草 / Air 薄荷 / Glue 蜜桃**。
旋钮值决定该色在一条 256 级颜色查找表上的"势力范围"，
频谱的柱子与粒子的颜色都从这张表上取，所以整屏配色永远一致。

用的是**高斯软分配**而不是硬切分：每色在自己区间的中心权重最高，
区间宽度由旋钮值决定。硬切分会在边界上留一道生硬的接缝。

粒子每颗带一个固定的 `u`（颜色轴上的位置 0..1），颜色 = `palette.at(u)`。
`u` 均匀分布，所以权重一变，粒子的颜色分布**立刻**跟着变 ——
不用等老粒子飘走、新粒子生成。频谱能量还会驱动它们：
声音一起来，粒子浮得更快、更亮、更大。

## 几个设计决定

- **饱和必须是非对称的**。`tanh` 是奇函数，只能产生奇次谐波，听感是"硬、刺"。
  温暖感来自偶次谐波，只能由非对称传递函数产生 —— 所以正负半周用不同驱动增益。
- **均衡只能串联**。并联（干湿混合）会改变滤波曲线的形状，还会和干信号打架。
- **压缩器的包络必须在线性域做**。在 dB 域平滑的话，信号每次过零点
  `log10(|x|)` 砸到 −100 dB 底，包络永远爬不到阈值以上。
- **响度中性不能靠固定的 makeup gain**。染色造成的衰减随输入电平变化，
  只能实时测、实时补。
- **非线性必须在过采样下算**，否则谐波会折叠回可听频段。
- **饱和要两级叠加**。单级再怎么推也只是在波形上捏一下；Preamp 压过之后
  Output 再压一次，谐波密度才上得去。这是"猛"的来源。
- **界面必须做冒烟测试**。DSP 回归全绿不代表界面不崩 ——
  曾经 `setSize()` 写在构造函数第一行，同步触发 `resized()` 时旋钮容器还是空的，
  宿主一打开界面就 SIGSEGV，而 11 项 DSP 测试一项都没发现。
  现在每次改 UI 都会跑一遍 Standalone 二进制确认存活。
